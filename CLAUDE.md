# Working on Planora

Privacy-first planning app for students and teachers: Vite + React + TypeScript, Electron (desktop), Capacitor (Android), PWA (web and iPhone). UI in English and Dutch.

## Where things live
- `src/domain/` – pure planning logic (scheduler, estimator, replan, busy times, categories, insights). Imports only `date-fns` and other domain files: no React, no database, no network. Every module has a `*.test.ts` next to it; new logic gets tests there.
- `src/data/` – local storage and privacy: `db.ts` (Dexie schema), `repo.ts` (which fields are encrypted), `crypto.ts`, `backup.ts`, `store.ts` (Zustand app state), `sync/` (end-to-end encrypted OneDrive sync between the owner's devices).
- `src/features/` – pages and dialogs (Today, Calendar, Inbox, Review, settings, …). Keep logic out of components; put it in `domain/` or `data/`.
- `src/components/` – shared UI pieces. `src/lib/` – small helpers (platform detection, formatting, files, updates, bug reports).
- `src/integrations/` – Microsoft (Outlook/Teams), Google Calendar, `.ics` import.
- `src/i18n/` – `en.json` and `nl.json`. Every user-facing string goes through i18n, added to **both** files.
- `electron/` – desktop main process, preload, OAuth, updater. `android/` – generated by Capacitor (`npm run cap:sync`); don't hand-edit web assets there.
- `e2e/` – Playwright tests (web and desktop).

## Commands
- `npm run dev` – dev server on port 5173.
- `npm test` – unit tests (Vitest). `npx vitest run <file>` for one file.
- `npm run lint` – Biome lint and format check. `npm run format` – fix formatting and safe lint issues.
- `npm run build` – type check and production build.
- `npx playwright test` – web e2e. `npm run e2e:desktop` – desktop e2e.

A hook formats every file you edit with Biome and reports lint errors it can't fix. Fix those right away; don't disable rules to silence them without asking.

## Before building a new feature
Run the `spec-sharpener` skill on the idea first. Show the owner the resulting spec (what's in, what's cut, the riskiest unknown) and build only after they agree.

## Before merging any change
This includes changes the daily bug-report routine merges itself.
1. These must pass: `npm test`, `npm run lint`, `npm run build`, and `npx playwright test`. If anything in `electron/` changed, also `npm run e2e:desktop`.
2. Run the `ship-inspector` skill on the diff.
   - Fix the bugs and security issues it reports, then run the checks again.
   - Don't act on its "one decision worth discussing". Report it to the owner.
3. If a skill isn't available in the session, continue without it and say so in your summary.

## Never without the owner's OK
- Changes to privacy, security, OAuth scopes, the CSP (`csp.cjs`), encryption, the sync file format or data model, the updater (`electron/updater.cjs`), or `.github/workflows`.
- Creating or pushing a version tag (`vX.Y.Z`). A tag starts the release workflow, which publishes installers and an update to every user.
- Changing the app ID (`app.planora`), Android signing setup, or anything that touches the signing key. Never commit a key, keystore or `.env` file.

## Data model rules
- Never edit an existing `this.version(n)` in `src/data/db.ts`. Schema changes get a new version with an upgrade function, plus a test that old data survives the upgrade.
- Data must stay readable by older app versions during sync: the merge code in `src/data/sync/` must tolerate fields it doesn't know.
- Never log task content, titles or notes. Logs and sync logs hold counts only.

## Handoff
`NEXT-STEPS.md` is the owner's status page. Read it at the start of a session; at the end, update it with what's done and what needs the owner, in plain language.
